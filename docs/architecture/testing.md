# Testing

Use Vitest throughout. Domain tests cover progress strategies, level/balance separation, habit schedules, streaks, timezone boundaries, minimum actions, deterministic challenge modes, daily caps, percentage improvement and incomplete observations. Contract tests protect validation, mass assignment and PATCH semantics.

Angular's unit-test builder compiles templates and runs Vitest in jsdom. Tests exercise HTTP credentials/loading/errors/retries, stale-response rejection, accessible field IDs, progress bounds, retry actions and bilingual/theme/motion preferences. Browser tests are responsible for real layout and overlay behavior.

Integration suites boot the actual NestJS app and use Supertest against migrated local PostgreSQL. They verify auth/recovery, origin protection, ownership, transaction races, duplicate XP, reward overdraft/refund, immutable challenge snapshots/results, private friend/challenge serialization, admin roles/content, notification preferences, erasure and audit history. Fixtures are isolated and do not rely on production data.

Coverage scopes are explicit: domain/contracts and backend source, with 80% statements/functions/lines and 70% branches. Reports use separate sibling directories, `coverage/domain` and `coverage/api`, so cleaning one report cannot delete the other's temporary files. Backend startup is exercised by E2E and excluded from integration instrumentation. Explicit DI avoids generated reflection branches; production and tests use the same setting. Never add coverage-ignore directives or reduce thresholds merely to get green checks.

Playwright starts production customer/admin builds and a dedicated API against a fresh random `mirhal_e2e_*_test` database. It covers registration/onboarding, linked work, habits/check-in/quests, XP/rewards, feedback/admin, social challenges, mobile widths, RTL/themes/reduced-motion and axe checks. Failures retain ignored traces/screenshots for diagnosis. These artifacts can contain test account or personal fixture data and are not source assets.

Run the commands in the README in order after changes. A build is necessary before E2E. Avoid simultaneous integration runs against the same database. CI runs all validation stages and uploads only failure artifacts with short retention; it does not deploy.

Critical interaction tests block previously installed service workers so Playwright's explicit API fixtures can reach the server. A short valid challenge deadline allows the actual activation, scoring and completion transactions to run during E2E without a production time-travel endpoint. PWA policy is independently inspectable in the generated `ngsw.json` and source configuration; API responses are excluded.

Planning/recovery regressions cover merged date validation and database constraints, project/goal consistency, custom rest days, completed weekly commitments, atomic Habit Lab adjustments, KEEP semantics and accessible schedule inputs. Browser suites additionally save/reload advanced planning fields, project milestones, subtasks, unsaved experiments and a temporary API failure followed by retry. `node tools/browser-smoke.mjs` checks running development applications and their configured database using environment-provided demo credentials; it signs in and reads both applications without editing personal work.

The 28 September hardening suite covers malformed/oversized JSON, concurrent login/reset/suspension, expired refresh, block ownership, version 2 scoring, future-start tasks, dashboard data minimization, challenge cancellation on erasure, and accurate moderation audits, and raw-SQL date/timestamp behavior in both positive and negative database timezone offsets. SMTP failure is injected through the mail adapter to test usable registration and verification retry; this does not certify external email delivery.

Integration and E2E bootstrap explicitly remove inherited Vercel/Blob/SMTP/demo credentials, use local attachment directories, and select isolated database URLs. The test Nest bootstrap surfaces startup exceptions instead of aborting the process.

Route inspection covers 320, 360, 390, 412, 480, 768, 1024, 1280, 1440 and 1600 pixel widths for seventeen customer and thirteen admin routes, in English/light and Arabic/dark. Axe evaluates those routes at desktop/light and mobile/dark. Dashboard/Today have additional width/accessibility checks. Ignored screenshots are written under `.local/audit/screenshots/`. The help interaction test selects the twelve connected domain stages and both added personalization/privacy stages, checks beginner-mode reset, and verifies Arabic/reduced-motion behavior.

After building, run `npm run test:performance` separately from integration tests. It accepts only a localhost `_test` database, creates and cleans disposable fixtures, samples dashboard latency/query count/payload size at one and one hundred habits, and records an indexed `EXPLAIN ANALYZE` plan in `.local/audit/api-performance.json`. These local samples are diagnostic, not production capacity or field percentiles. Current results and release limitations are in [the final audit](../audit/final-audit.md).

Attachment erasure has an injected storage-failure test: the account and metadata are erased, the private key remains queued, and a newly constructed worker successfully deletes the file and queue record. Cloud delivery/deletion still needs credentialed staging verification.
