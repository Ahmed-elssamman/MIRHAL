## Infrastructure and security findings

- The code selects Resend for production, but the live API currently reports email disabled. Render Free web services block outbound SMTP ports 25, 465, and 587, so production must use the HTTPS provider. See [Render Free instance limitations](https://render.com/docs/free).
- Resend is already implemented with a 10-second timeout, one bounded retry for network/5xx errors, and a stable idempotency key. Provider response bodies, email addresses, and tokens are not logged.
- Tokens are random, stored hashed, purpose-bound, rate-limited, expiring, and single-use. Password reset revokes all active sessions and invalidates other outstanding reset tokens. Forgot-password always returns a generic response. The post-reset notice uses the consumed token record ID only as an idempotency input; it contains no secret.
- Verification and recovery requests send synchronously. The post-reset security notice is attempted after the password transaction commits and is best-effort. UI success describes provider acceptance/request receipt, not proof of inbox delivery.
- Render Blueprint previously set `MAIL_MODE=enabled`, but the actual schema accepts only `development`, `disabled`, or `production`. The Blueprint now uses `production`, matching API validation and `mailConfig`.
- Resend remains the selected provider. Resend retains an `Idempotency-Key` for 24 hours, so invitation keys include the UTC day and personalization inputs to keep same-day retry payloads stable. [Resend idempotency documentation](https://resend.com/changelog/idempotency-keys).
- A verified sender domain and DNS authentication records, `RESEND_API_KEY`, and `SMTP_FROM` are external setup requirements. Production HTTP check on 2026-10-29 returned API health 200 at `https://mirhal.onrender.com/api/health`, but `GET /api/auth/capabilities` returned `{"emailDelivery":false}`. In this code, that means production email is disabled (`MAIL_MODE=disabled`), so invitation, verification, and recovery sends cannot work in the currently observed production configuration.
- Production web root returned 200 at `https://mirhal-web.vercel.app/`; `/mirhal-email-logo.png` returned 404, and `https://mirhal-admin.vercel.app/` returned 404. The new email logo and customer/admin deployment have not been published. The ignored local Vercel staging directories have been linked to the correct `mirhal-web` and `mirhal-admin` projects. Vercel and Render CLIs are authenticated. The latest Render deploy built successfully but failed during startup because a stale guard required BLOB or attached-disk storage even though attachments are persisted in PostgreSQL. That guard is removed locally; this fix has not yet been deployed. The live service remains on its previous deployment and reports email disabled.
- Resend accepts email requests with a provider message ID. The adapter records `accepted` and the safe provider message ID when supplied; it does not claim delivered status.
- Local `.env` selects the development file provider by default and contains no Resend API key. Production provider settings and delivery were not changed or claimed verified.

## Brand and template implementation

- The shared auth template uses the repository's MIRHAL mark, teal `#0e7165`, deep green `#183a35`, light canvas `#f5f7f4`, and email-safe inline styles.
- The public customer app serves `apps/web/public/mirhal-email-logo.png` at `${APP_URL}/mirhal-email-logo.png` for supported email clients. HTML also has a text brand fallback, and includes a plain-text alternative.
- Verification, reset, security notice, and new friend invitation emails include localized subject, title, greeting, CTA, relevant expiry, unsolicited-request guidance, fallback copyable URL, and a support footer. Arabic is RTL; token URLs are explicitly LTR. English is LTR.
- The support footer uses optional backend-only `SUPPORT_EMAIL`; when unset it links to the existing public help page.
- Layout uses nested presentation tables, inline CSS, system font fallbacks, fixed-width button tables, and no scripts, external stylesheets, or remote backgrounds. Actual rendering differs by mailbox; a controlled inbox check is still required.
- Narrow browser preview artifacts: `.local/audit/email-template-preview-ar.png` and `.local/audit/email-template-preview-en.png` (390 px viewport; the local preview fulfills the logo request from the checked-in public PNG).
